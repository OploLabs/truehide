TrueHide — Privacy audit

Network requests

The only external network request that occurs in the shipped site is:

  @import url("https://fonts.googleapis.com/css2?family=Inter:wght@400;500;600;700;800&display=swap");

This was the sole Google Fonts @import in shared/base.css. As of this audit it is replaced with a self-hosted variable font fonts/inter-latin.woff2. The site now makes zero external network requests while processing user files.

All other requests are same-origin:

  • fetch(shared/footer.html) in shared/base.js — fetches the canonical footer from the site root; guarded against cross-origin.
  • Service Worker fetch(event.request) in sw.js — only handles same-origin GET requests (url.origin !== self.location.origin returns early); user files are never sent off-device.

Since there are no analytics, telemetry, or advertising scripts, no user data leaves the device.

Third‑party dependencies

All processing libraries are vendored locally and never loaded from a CDN:

  • pdf.js 3.11.174 — vendored at app/trueflatten/lib/pdf.min.js and pdf.worker.min.js. Used only by TrueFlatten for PDF rasterization and re-export verification.
  • jsPDF 2.5.1 — vendored at app/trueflatten/lib/jspdf.umd.min.js. Generates the output PDF; its own metadata (producer, creator) is written into the exported file, but source PDF metadata cannot leak because the output is built from a rasterized canvas.

No other external scripts, frameworks (React, Vue, etc.), or build tools are used. The site is pure HTML / CSS / vanilla JavaScript.

Local storage

The only key persisted in localStorage is:

  truehide-theme

It stores the user's colour‑scheme preference (light or dark). No file contents, no IDs, no tracking tokens.

Temporary / in‑memory resources

  • TrueFlatten: the whole PDF is kept in an ArrayBuffer in memory; pdfDocument is not explicitly destroyed on re-open. Fix: add pdfDocument.destroy() when a new PDF is loaded.
  • TrueBlur: canvas object URLs are revoked after image decode and on beforeunload (currentObjectURL).
  • TrueCrop: object URLs are revoked in a finally block after export.

PDF export verification

The exported PDF is built entirely from rasterized page renders. The source PDF's text, annotations, form fields, embedded files, and metadata are not included in the output because jsPDF reconstructs the PDF from the drawn image. However:

  • The jsPDF library embeds its own XMP metadata (producer, creator, etc.) into the export. This is app‑level metadata, not user data, but it means the export is not a "clean" source‑preserving PDF.
  • No embedded-file or annotation detection/warning is shown during export. The plan adds a pre‑export warning list (annotations, AcroForm fields, embedded files) and a post‑export verification step that re‑opens the exported PDF with pdf.js, extracts text from every page, and reports whether any recoverable text exists.
  • Users are warned that "complete sanitization is not guaranteed" because rasterization irreversibly removes vector data but may leave hidden text in certain PDF production contexts.

Threat model & limits

TrueHide's security claim is: all file processing happens entirely in the browser. The documented limits are:

  • Any data that is already rasterized or rendered as an image cannot be "un‑redacted" — the redaction is permanent at the pixel level.
  • PDF metadata (title, author, producer, creator) that jsPDF writes into the export is app‑level, not user data, but it means the output is not a "zero‑metadata" PDF.
  • Google Fonts @import was the only formerly external request; it has been self‑hosted.
  • Canvas‑based effects (TrueBlur pixelate/blocks/solid) are visual obfuscation only; they do not permanently remove original pixel data.
  • No network sandbox or OS-level sandboxing is relied upon — the site works over http(s) and also degrades gracefully on file:// (offline/without service worker).

Vulnerability disclosure

If you discover a security or privacy issue in TrueHide, please report it responsibly by opening an issue on the GitHub repository (github.com/OploLabs/truehide/issues/new). All reports are acknowledged within 48 hours. The project follows a coordinated disclosure policy: the maintainers will work with the reporter to understand the issue, assess impact, and publish a fix. There is currently no bug‑bounty program.
